## 6. 마이페이지 (데모) (2026.11.04)

**왜**: 스팟메뉴의 「마이페이지」가 갈 곳이 없었고, 주문하고 나면 다시 확인할 방법이 없음.

**만든 것** (`sub/mypage/`, `scss/mypage.scss`)
- **로그인(데모)**: 로그인 페이지에서 입력하면 **이메일만** 브라우저에 저장(비밀번호는 저장하지 않음)하고 마이페이지로 이동. 스팟메뉴 「로그인」이 「로그아웃」으로 바뀜
- **인사 · 요약**: 「○○님, 안녕하세요」, 적립금 · 쿠폰 · 주문 수. 로그인 전에는 「손님」과 로그인 버튼
- **주문 내역**: 결제할 때마다 주문 목록(`soha_orders`)에 최근 10건까지 저장. 날짜 · 주문번호 · 「불렛저널 외 1개」 · 결제 금액
- **다운로드함**: 주문한 상품을 이름 기준으로 한 번씩 모아 다운로드 버튼(데모 알림)
- **최근 본 상품**: 헤더 팝업 · 모바일 메뉴와 같은 데이터
- 주문 내역 · 다운로드함 · 최근 본 상품 바로가기 버튼, 비어 있을 때 안내 문구
- 검색 노출 제외(`noindex`), 「포트폴리오용 데모」 안내 문구

**같이 찾은 버그**
| 문제 | 수정 |
|---|---|
| 7개 페이지 헤더 팝업 예시 이미지 경로에 슬래시가 두 번(`../..//img/`) | `../../img/`로 수정 |
| 마이페이지를 만들며 복사한 채팅 · 푸터 로고가 페이지 폴더 안 `img/`를 가리켜 깨짐 | 공용 `img/` 경로로 수정 |

**확인**: 결제 → 로그인 → 마이페이지(주문 1건 · 다운로드 2개 · 최근 본 상품 3개) → 로그아웃 흐름을 PC · 휴대폰에서 실행, 오류 없음. 19개 페이지 깨진 이미지 · 가로 스크롤 없음.

## 5. 헤더 개편 — 햄버거 메뉴 · 스팟메뉴 (2026.11.04)

**왜**: 1023px 이하에서 헤더가 두 줄(약 104px)로 꺾이고, 휴대폰에서는 오른쪽 메뉴가 잘림(「알립니다」가 「알」만 보임). 사람 아이콘만으로는 로그인인지 마이페이지인지 알기 어려움.

**과정**: 햄버거 · 하단 탭 바 · 가로 탭 3가지를 비교해 햄버거로 정함 → 로그인 등을 스팟메뉴로 두는 A안(헤더 위 줄) · B안(메뉴 안)을 실제 화면에 입힌 시안으로 비교해 A안으로 정함.

**스팟메뉴 (PC · 모바일 공통)**
- 헤더 위 작은 글자 줄 **로그인 · 회원가입 · 마이페이지 · 고객센터**, 헤더와 같은 크림색
- 스크롤하면 위로 사라지고 아래 헤더만 고정
- PC는 12칸 그리드상 아이콘 오른쪽에 120px 여백이 있어 스팟메뉴 끝을 아이콘 끝에 맞춤
- 마이페이지는 페이지가 생기기 전까지 로그인으로 연결, 고객센터는 「궁금해요(FAQ)」로 연결
- 로그인 · 마이페이지가 스팟메뉴로 옮겨 가서 **PC의 👤 아이콘은 뺌** (🔍 🛒 🕒은 유지)

**모바일 헤더 (1023px 이하)**
- 한 줄 56px: **☰ · 로고(가운데) · 🔍 · 🛒(담긴 개수 표시)**
- ☰ 메뉴: 왼쪽에서 열리는 드로어
  - 디지털 문구는 눌러서 펼치기(전체 · 다이어리 · 플래너 · 저널 · 스티커 · 무료)
  - **최근 본 상품**을 사진으로 표시 (헤더의 🕒 아이콘은 모바일에서 숨김)
  - 사용법 알아보기 · 고객센터 버튼
  - 지금 보고 있는 페이지 메뉴는 굵게 표시 (`aria-current`)
  - Esc · 바깥 어두운 영역 터치로 닫기, 열면 닫기 버튼으로 / 닫으면 ☰ 버튼으로 포커스 이동, 메뉴가 닫혀 있을 때는 `inert`로 탭 이동 차단
  - 메뉴 내용은 JS가 PC 메뉴 링크를 읽어 만들어서 18개 페이지에 같은 HTML을 복사하지 않음
- 상세 페이지 「상세정보 · 후기 · Q&A」 이동 위치를 줄어든 헤더 높이에 맞춤 (110 → 62px)

**같이 찾은 버그**
| 문제 | 수정 |
|---|---|
| 로그인 페이지 메뉴의 「궁금해요」 링크가 `../.4_faq/`로 깨져 있음 (PC 포함) | `../4_faq/`로 수정 |
| 상품 목록 · 상세 7개 페이지는 PC 메뉴에 하위 카테고리가 없어 모바일 메뉴가 페이지마다 달라짐 | 카테고리 목록을 고정하고 경로만 계산 |
| FAQ 페이지에서 채팅의 「사용법 자세히 보기」 링크가 깨짐 (메뉴의 자기 자신 링크가 `href="#"`) | 사이트 루트(main.js 위치) 기준으로 경로 생성 |

**확인**: 18개 페이지 모두 메뉴가 열리고 JS 오류 · 깨진 링크 없음, 가로 스크롤 없음. 메뉴 열기 · 펼치기 · Esc 닫기 · 포커스 이동 · 장바구니 개수 · 최근 본 상품 표시를 직접 테스트.

## 4. 키워드 추천 — 휴대폰만 글자 탭 + 카드 (2026.11.04)

**왜**: 휴대폰에서 동그라미 키워드 8개가 두 줄로 크게 자리를 차지하고, 상품 이름은 마우스를 올려야 보여서 터치 화면에서는 볼 수 없음.

**바꾼 것 (768px 이하만, PC · 태블릿은 원래 디자인 그대로)**
- 동그라미 키워드 → `📅 #계획` 같은 **글자 탭 한 줄** (가로 스크롤, 선택하면 굵게 + 갈색 밑줄)
- 사진 위 검은 막 글자 → **둥근 사진 아래 상품명 · 가격** 2칸 카드
- 글자 링크를 카드 전체로 넓혀서 **사진을 눌러도 상품으로 이동**
- 이모지는 HTML을 바꾸지 않고 휴대폰 CSS(`::before`)에서만 붙임

**과정**: 처음에는 PC까지 탭 + 카드로 바꿨다가, PC는 원래 디자인을 유지하기로 해서 되돌리고 휴대폰 스타일만 추가함.

**확인**: PC(1440 · 1024px)가 이전과 픽셀 단위로 같음. 휴대폰에서 사진을 터치하면 상세 페이지로 이동.

## 3. 떠 있는 버튼 · 채팅 · 모바일 사진 (2026.11.04)

### 떠 있는 버튼
**왜**: 휴대폰 오른쪽에 사용법(64px) · 채팅(52px) · TOP(44px)이 쌓이고 왼쪽 아래 안내 팝업(100px)까지 있어 상품을 가림.

- 휴대폰에서 TOP · 채팅 · 사용법을 **40px로 줄여 오른쪽 아래 한 줄**로 정리
- 동그란 안내 팝업 → **왼쪽 아래 얇은 띠**
- TOP 버튼은 **400px 이상 스크롤했을 때만** 표시 (PC도 동일)
- 상품 카드의 장바구니 담기 버튼 40px → **30px** (휴대폰)
- 채팅창을 열면 같은 자리의 사용법 버튼은 숨김

**같이 찾은 버그**
| 문제 | 원인 | 수정 |
|---|---|---|
| 채팅 버튼이 눌리지 않을 때가 있음 | 떠 있는 버튼에 `z-index`가 없어 상품 카드의 장바구니 버튼이 위에 겹침 | 떠 있는 버튼에 `z-index` 지정 |
| 사용법 버튼의 ✕(닫기)가 동작하지 않음 | JS는 `.how_use_close`를 찾는데 HTML 버튼에 클래스가 없음 | 13개 페이지 버튼에 클래스 추가 |

### 채팅 (자동 응답 데모)
**왜**: 입력칸만 있고 아무 반응이 없는 모양뿐이었음.

- 빠른 질문 버튼 **다운로드 · 환불 · 필기앱 · 쿠폰 · 운영시간** + 직접 입력
- 입력한 문장의 키워드로 FAQ 내용을 바탕으로 답변. 준비된 답이 없으면 「자주 묻는 질문」 링크 안내
- 상단 문구를 「자동 응답 상담 (데모)」로 바꿔 실제 상담원이 아님을 표시
- 입력값은 `textContent`로만 넣어 HTML이 실행되지 않게 함
- 링크는 메뉴의 FAQ 경로를 기준으로 만들어 페이지 깊이와 상관없이 동작
- 답변 내용은 `js/main.js`의 `answers` 목록에서 수정

### 모바일 사진 크기
- 상품 카드: 같은 줄 카드 높이 통일, 글자 영역을 줄여 사진이 먼저 보이게
- 후기 사진: 정사각형 → **4:3** (2×2 카드가 덜 길어짐)
- 인스타그램: 2×2 큰 사진 → **한 줄 4장**

## 2. 반응형 마무리 (2026.11.03 · PR #2로 사이트 반영)

**왜**: 반응형 기본 적용 후 17개 페이지를 1024 · 768 · 390px에서 하나씩 확인해 보니 일부 화면이 깨져 있었음.

| 문제 | 원인 → 수정 |
|---|---|
| 1280px 이하에서 인스타그램 사진 4장이 사라짐 | 그리드 칸 안에 PC용 `float`가 남아 너비가 0 → `float` 해제 |
| 후기 카드 너비 · 높이가 제각각 (메인 · 솔직후기) | 앞 3장에만 PC용 `.mr` 여백(15px)이 남음 → 해제. 상품 정보를 썸네일 \| 상품명 · 리뷰 수 2칸으로 정렬, 세로 사진도 정사각형으로 잘라 높이 통일 |
| 태블릿에서 상품명이 두 줄로 꺾임 | 1280px 이하에서 24px → 20px |
| 1024px 푸터가 들쭉날쭉, 휴대폰에서 버튼이 로고에 밀림 | 1220px 이하 2칸 그리드, 로고 영역 300px 유지 |
| 검색결과 검색창이 화면 끝에 붙고 아이콘이 줄바꿈 | 좌우 16px 여백, flex로 한 줄 정렬 |
| 회원가입 입력칸이 약 20px로 너무 작음 | 휴대폰에서 36px 높이 · 16px 글자(아이폰 자동 확대 방지), 이메일 줄 정렬. `input[type=text]`가 `.email`보다 우선순위가 높았던 문제도 수정 |
| README가 「데스크톱 중심 · 반응형 적용 예정」으로 남아 있음 | 현재 상태로 수정, 개선 과정 표에 추가 |

**확인**: 모든 수정은 미디어쿼리 안에만 넣음. PC(1440px)가 수정 전과 픽셀 단위로 같음. 17개 페이지 모두 가로 스크롤 없음.

## 참고
- 스타일은 `scss/`에서 고친 뒤 `npx sass@1.83.0 --no-source-map scss:css`로 컴파일하고 `css/`도 함께 커밋 (GitHub Pages는 `css/`를 그대로 사용)
- 확인한 화면 폭: 1440 · 1280 · 1024 · 768 · 640 · 390px
- 남은 확인 사항: 결제 페이지(`sub/checkout/`) 푸터만 실제처럼 보이는 계좌번호 · 사업자번호 · 주소를 쓰고 있음 (다른 페이지는 `000-0000` 같은 예시 값)
